# Ads 라이브 코딩: 우선순위와 설명까지 연습하기

이 문서는 이 저장소의 60분 모의 연습 가이드입니다. 실제 토스의 시간 배분·채점표가 아닙니다. 외운 답을 말하는 것보다 **관찰한 사실과 근거를 연결하는 과정**을 연습합니다.

## 처음 코드를 받으면

금액의 단위, 계정 경계, 보고 기간, 허용 상태 전환, 서버의 성공·실패 계약부터 확인합니다. 모든 질문을 한꺼번에 던지기보다 현재 판단에 필요한 미확정 조건을 묻습니다.

> “목록 조회와 예산 변경 흐름을 먼저 따라가겠습니다. 금액은 원 단위 정수인지, 요약은 현재 페이지인지 전체 필터 결과인지 확인하고 싶습니다. 이후 주요 시나리오를 재현해 영향이 큰 변경 경로부터 수정하겠습니다.”

## 우선순위 결정 예시

아래 우선순위는 재현된 영향을 바탕으로 한 예시입니다. 번호를 기계적으로 암기하지 않습니다.

| 상황                       | 판단 근거                    | 첫 행동                           |
| -------------------------- | ---------------------------- | --------------------------------- |
| 다른 계정/광고에 수정 요청 | 잘못된 대상 변경 가능        | 쓰기 대상 식별을 먼저 보호        |
| 미승인 광고의 시작 요청    | 정책 위반 가능               | 서버 판정 확인, UI 전환 조건 수정 |
| 저장 실패를 성공 표시      | 잘못된 확정 상태와 복구 실패 | 성공·실패 경로 분리               |
| 잘못된 CTR·보고 기간       | 예산 판단·보고 오류          | 계산 계약과 경계 재현             |
| 일부 실패를 전체 성공 표시 | 필요한 후속 작업 누락        | 결과별 상태와 재시도 범위 표시    |
| 작업이 멈추는 테이블       | 운영 자체 불가능             | 병목 측정 후 최소 개선            |
| 경미한 네이밍·간격         | 기능 영향 작음               | 핵심 기능 수정 이후               |

발생 빈도만으로 정하지 않습니다. 드물어도 영향이 크고 복구가 어려운 변경은 먼저 다룹니다. 반대로 아직 추측인 위험을 확인된 장애처럼 말하지 않습니다. 남은 시간과 의존성도 고려합니다.

## 재현한 사실과 추정 분리

```text
관찰: A에서 입력한 금액이 B ID를 담은 요청으로 전송됨
기대: 저장 대상과 초안의 소유 광고가 같아야 함
영향: 다른 광고 예산을 변경할 가능성
미확인: 서버가 version/권한 조건으로 이 요청을 거절하는가
우선 조치: ID별 편집 세션 분리와 제출값 고정
검증: A→B 이동, A의 늦은 응답, 같은 A 재조회
```

## 60분 연습의 시간 배분 예시

| 구간    | 목표                               |
| ------- | ---------------------------------- |
| 0~8분   | 요구사항·화면·데이터 흐름 파악     |
| 8~15분  | 구체적인 결함 재현과 우선순위 설명 |
| 15~40분 | 핵심 결함을 하나씩 수정하고 테스트 |
| 40~52분 | 실패·재시도·경계 조건과 회귀 검증  |
| 52~60분 | 남은 위험·검증 결과·선택 근거 정리 |

코드 읽기 시간이 별도로 주어졌다면 면접 시간과 구분합니다. 재현이 막혔을 때 계속 시간을 쓰기보다 확인된 부분과 가설을 나누어 면접관과 범위를 맞춥니다.

## 고치기 전·중·후에 할 말

**고치기 전:** “세 가지 문제를 확인했습니다. 다른 광고에 저장될 수 있는 경로를 먼저 고치겠습니다. 실제 서버 적용 여부는 아직 미확인이지만 제출 대상과 초안이 불일치하는 것은 재현했습니다.”

**고치는 중:** “지금은 상태 라이브러리를 바꾸지 않고 세션 경계와 제출 대상만 고정하겠습니다. 기존 폼 구조를 유지해 변경 범위를 줄이겠습니다.”

**검증할 때:** “수정 전에는 A 초안이 B 요청에 들어가 테스트가 실패했습니다. 수정 후 이 경로와 서버 거절 후 재시도가 통과했습니다. 실제 서버의 권한 검사는 이 컴포넌트 테스트가 보장하지 않습니다.”

**시간이 부족할 때:** “계정 경계와 실패 복구는 수정했습니다. 집계 기간 경계는 재현만 했고 수정하지 못했습니다. 다음에는 KST 하루 구간의 시작·끝 테스트를 추가하겠습니다.”

## 종합 변형 문제 3개와 해설 방향

### A. 금융 광고 성과 대시보드

기능: 계정 선택, 기간 조회, 캠페인 목록, 요약 카드, 정렬·페이지네이션.

학습용 결함 5개: 계정 누락 query key, 행 CTR 평균, 성과 없는 항목 누락, 날짜 경계 혼용, 현재 페이지에서만 전체 정렬.

해설 순서: 계정 데이터 격리 → 기간/집계 계약 → 목록 보존 → 전체 정렬 범위. 05·09·01·02·06의 코드를 조합합니다. 계정 A·B 동일 ID, 노출 규모가 다른 2행, 성과 누락, 자정 경계, 2페이지 데이터가 1페이지보다 큰 비용인 경우를 검증합니다.

### B. 광고 운영과 예산 변경

기능: 상세 패널, 예산 저장, 심사 상태, 운영 토글, 선택 항목 일괄 중지.

학습용 결함 5개: 항목 간 초안 공유, version 없이 저장, 심사 상태 무시, 낙관적 변경 복구 누락, 일부 실패를 전체 실패/성공으로 처리.

해설 순서: 잘못된 대상 쓰기 차단 → 허용 상태 전환 → 저장 충돌/실패 복구 → 일괄 결과 처리. 10·04·03·08을 연결합니다. A→B 전환, 동료 version 갱신, 미승인 광고, 성공·거절·결과 불명의 혼합 응답을 검증합니다.

### C. 대량 리포트와 내보내기

기능: 큰 테이블 검색, 조회 갱신, 보고서 생성, 완료 폴링, 필터 변경.

학습용 결함 4개: 반복 find 병목, 오래된 조회 결과 반영, 현재 페이지만 내보내기, 완료 후에도 폴링.

해설 순서: 결과 소속과 내보내기 범위 → 작업 종료 정리 → 측정한 병목 개선. 07·12·11을 연결합니다. 큰 입력, 응답 순서 역전, 120개 중 20개 페이지, 완료·실패 후 추가 요청 부재를 검증합니다.

이 세 묶음은 종합 문제 설계안과 공개 해설입니다. 새 독립 앱 3개가 생성된 것은 아닙니다. 수업별 코드와 실행 가능한 도메인 함수로 학습한 뒤, 사용자가 실전 연습을 요청하면 별도의 `practice` 과제로 제작합니다.

## 외우는 대신 확인할 준비 기준

- 코드 없이 증상과 재현 조건을 설명할 수 있다.
- 고친 코드가 무엇을 보장하고 무엇을 보장하지 않는지 말할 수 있다.
- 요구사항이 하나 바뀌면 기존 해결법의 한계를 지적할 수 있다.
- 테스트를 구현 그대로 따라 쓰지 않고 기대 동작으로 작성할 수 있다.
- 확인하지 못한 사실을 숨기지 않고 다음 확인 방법을 설명할 수 있다.

추가 기반이 필요하면 JS Promise·클로저·참조, React 렌더·Effect·폼, TypeScript union·unknown, HTTP 상태·인증, 테스트 mock과 비동기 완료 제어를 다시 학습합니다. 9개 공통 이론과 12개 사례는 학습 출발점이며 면접의 모든 질문을 보장하지 않습니다.
