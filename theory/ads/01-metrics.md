# 01. 카드 광고 대시보드의 전체 CTR이 틀린다

## 개념부터 풀어보기

CTR(클릭률)은 노출 중 클릭이 발생한 비중이고, CPC(클릭당 비용)는 광고비를 클릭 수로 나눈 값입니다. `impressions`는 노출 수, `clicks`는 클릭 수, `spendWon`은 원 단위 광고비입니다. 노출 1,000회·클릭 10회·비용 5,000원이면 CTR은 1%, CPC는 500원입니다.

‘광고별 CTR의 평균’과 ‘전체 노출 중 클릭 비중’은 서로 다른 질문입니다. 아래 예시에서 A는 노출 10회, B는 990회인데 단순 평균을 내면 두 광고의 영향력이 같아집니다. 전체 CTR에는 노출 규모가 반영되어야 합니다.


## 요구사항과 Before

가상 카드 광고 A·B의 같은 기간·같은 통화·같은 집계 기준 데이터를 합쳐 표시합니다. CTR은 클릭/노출 × 100, CPC는 비용/클릭입니다. 분모가 0이면 계산 불가를 `—`로 표시합니다. 원 단위 비용은 합산하고, 반올림은 표시할 때만 합니다.

```ts
const ctr = (rows.reduce((sum, row) => sum + row.clicks / row.impressions, 0) / rows.length) * 100;
```

## 재현과 우선순위

A는 10회 노출·1회 클릭(10%), B는 990회 노출·9회 클릭(약 0.91%)입니다. 단순 평균은 약 5.45%지만 전체는 10/1,000 = 1%입니다.

성과를 비교해 예산을 옮기는 화면이라면 잘못된 지표는 운영 판단에 영향을 줍니다. 표시 간격 같은 스타일보다 먼저 고칩니다. 다만 현재 다른 광고 계정에 잘못 저장하는 문제가 있다면 그 변경 경로부터 막는 것이 우선일 수 있습니다.

## After와 근거

```ts
const total = rows.reduce(
  (sum, row) => ({
    impressions: sum.impressions + row.impressions,
    clicks: sum.clicks + row.clicks,
    spendWon: sum.spendWon + row.spendWon,
  }),
  { impressions: 0, clicks: 0, spendWon: 0 },
);

const ctrPercent = total.impressions === 0 ? null : (total.clicks / total.impressions) * 100;
const cpcWon = total.clicks === 0 ? null : total.spendWon / total.clicks;
```

비율은 분자와 분모를 각각 합산한 뒤 다시 계산합니다. 평균값의 평균을 구하지 않습니다. `null`은 0%와 다릅니다. 노출 100·클릭 0은 CTR 0%이고 노출 0은 계산 불가입니다. CPC를 계산할 수 없다고 0원으로 보여주면 무료 클릭인 것처럼 오인할 수 있습니다.

이 함수는 유효한 비음수 데이터가 들어온다는 전제입니다. API 경계에서 NaN·음수·통화 혼합을 검증해야 합니다. 카드 신청 전환 수를 매출액으로 취급해 ROAS를 계산하지 않습니다. 전환 정의·귀속 기간·분모를 먼저 확인합니다.

## After 코드가 보장하는 것

1. `reduce`는 각 행의 노출·클릭·비용을 각각 더합니다. 초기값이 모두 0이므로 빈 배열도 계산할 수 있습니다.
2. 합산이 끝난 뒤 CTR·CPC를 구합니다. 이미 계산된 비율을 더하는 것이 아닙니다.
3. 분모가 0이면 `null`을 반환합니다. UI에서 `—`와 계산 불가 이유를 보여줄 수 있습니다.
4. 표시할 때만 반올림합니다. 행별 반올림 후 합산하면 중간 오차가 누적될 수 있습니다.

| 입력 | 기대 결과 | 이유 |
| --- | --- | --- |
| 노출 100, 클릭 0 | CTR 0%, CPC 계산 불가 | 노출은 있었지만 클릭당 비용을 계산할 클릭이 없음 |
| 노출 0, 클릭 0 | CTR·CPC 계산 불가 | 두 지표 모두 분모가 0 |
| 비용 100원, 클릭 3회 | 원본 CPC 100/3 | 정수 원 표시는 별도의 반올림 정책 |
| 성공적으로 조회한 빈 목록 | 합계 0, 비율 계산 불가 | 조회 실패를 빈 목록으로 바꿔 넣어서는 안 됨 |

‘같은 집계 기준’은 기간·시간대·대상 범위가 일치하고 중복 집계가 없다는 뜻입니다. 오늘 A 성과와 이번 달 B 성과를 합쳐 오늘의 성과라고 표시하면 안 됩니다. `NaN`은 숫자 계산이 성립하지 않았음을 나타내는 특수값이며 그대로 화면에 노출하지 않도록 입력을 검증합니다.

ROAS는 광고비 대비 매출액 비율입니다. 신청 건수는 매출 금액이 아닙니다. ‘전환’이 신청인지 승인인지, 광고 이후 며칠까지 발생한 행동을 성과로 인정하는지(귀속 기간)를 확인해야 서로 비교할 수 있습니다.

## 검증

- 위 A·B 데이터에서 CTR 1%인지 확인합니다.
- 클릭 0일 때 CPC가 null이고, UI가 `—`를 표시하는지 확인합니다.
- 비용 100원·클릭 3회의 원본 CPC는 100/3을 유지하고 표시만 반올림합니다.
- 요약이 전체 필터 결과인지 현재 페이지만인지 확인합니다.

## 면접에서 말하기

> “행별 CTR 평균은 노출 규모 차이를 반영하지 못합니다. 전체 클릭과 노출을 합산해 다시 계산하겠습니다. 운영자의 예산 판단에 영향을 주므로 표현 개선보다 우선하고, 0%와 계산 불가도 구분하겠습니다.”

**꼬리질문:** 필터 결과가 100개인데 20개만 받았다면?

**해설:** 20개로 계산한 값을 전체 합계로 표시하면 안 됩니다. 서버 요약을 받거나 전체 데이터를 확보해야 합니다. 지금 계산의 범위를 라벨에 명시하는 것도 중요합니다.
