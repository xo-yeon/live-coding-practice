# 09. 하루 리포트에 자정 근처 비용이 빠진다

## 개념부터 풀어보기

‘2026-09-27’은 달력 날짜이고 ‘2026-09-26T15:00:00.000Z’는 특정 시각입니다. 날짜 하나를 조회 구간으로 바꾸려면 어느 시간대의 하루인지 먼저 정해야 합니다. Z는 UTC 기준이라는 뜻이고 +09:00은 UTC보다 9시간 빠르다는 뜻입니다.

한국의 9월 27일 00:00과 UTC의 9월 26일 15:00은 같은 순간입니다. ISO 문자열에서 날짜가 하루 전으로 보인다고 잘못 변환된 것이 아닙니다.


## 요구사항과 Before

학습용 리포트는 Asia/Seoul 날짜 기준입니다. 2026-09-27 하루는 해당 지역 00:00부터 다음 날 00:00 직전까지입니다. API는 UTC ISO 문자열의 `[from, to)` 구간을 받습니다.

```ts
const from = new Date('2026-09-27').toISOString();
const to = new Date('2026-09-27T23:59:59').toISOString();
```

## 재현과 우선순위

첫 문자열은 UTC 자정 기준이고, 두 번째는 실행 환경의 로컬 시간대에 의존합니다. 기준이 섞일 수 있습니다. 밀리초 단위의 마지막 데이터도 23:59:59 종료값에서 빠집니다. 비용 합계가 달라지므로 집계 정확성 문제로 다룹니다.

## After

아래 코드는 이미 검증된 실제 달력 날짜를 입력받으며 현대 한국 시간(+09:00)만 지원하는 수업용 예제입니다.

```ts
const start = new Date('2026-09-27T00:00:00+09:00');
const end = new Date('2026-09-28T00:00:00+09:00');
const range = { from: start.toISOString(), to: end.toISOString() };
// from: 2026-09-26T15:00:00.000Z
// to:   2026-09-27T15:00:00.000Z
const inRange = (time: number) => time >= start.getTime() && time < end.getTime();
```

끝을 제외하는 구간은 인접 날짜에서 중복·누락을 피하기 쉽습니다. 마지막 시각을 23:59:59.999로 추측해 만드는 대신 다음 날 시작을 사용합니다. 서버도 같은 경계 규칙이어야 합니다.

하루를 무조건 24시간 더하는 코드는 일광절약시간이 있는 지역에 일반화할 수 없습니다. 다국가 제품에서는 서버가 제공한 경계나 시간대 지원 라이브러리를 사용하고 해당 지역의 전환일을 검사합니다. 예제의 +09:00 정책을 세계 공통 규칙으로 외우지 않습니다.

## 반열린 구간을 풀어 읽기

`[from, to)`는 시작은 포함하고 끝은 제외한다는 표기입니다. 즉 `from <= 데이터 시각 < to`입니다. 27일 보고서는 27일 00:00부터 28일 00:00 직전까지이고, 28일 보고서는 그 28일 00:00부터 시작합니다.

| 한국 시각 | 27일 보고서 포함 여부 |
| --- | --- |
| 26일 23:59:59.999 | 제외 |
| 27일 00:00:00.000 | 포함 |
| 27일 23:59:59.999 | 포함 |
| 28일 00:00:00.000 | 제외, 다음 날에 포함 |

종료를 23:59:59로 지정하면 그 뒤의 밀리초 데이터가 빠집니다. 다음 날 시작을 제외하면 저장소의 더 세밀한 시간 정밀도에도 ‘마지막 순간’을 추측할 필요가 없습니다. 서버의 비교 연산도 끝을 제외해야 같은 결과가 나옵니다.

## Date 코드에서 헷갈리기 쉬운 점

JavaScript의 표준 날짜 전용 문자열은 UTC 기준으로 해석됩니다. 시간대 없는 날짜·시간 문자열은 실행 환경의 로컬 시간대로 해석됩니다. 따라서 Before의 두 입력은 기준이 다를 수 있습니다. `toISOString()`은 이미 만들어진 시각을 UTC 문자열로 표현할 뿐, 처음부터 한국 자정으로 다시 해석해 주지 않습니다. [MDN Date 문서](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date)

`getTime()`은 시각을 밀리초 숫자로 바꾸므로 같은 기준의 숫자끼리 구간을 비교할 수 있습니다. 입력 날짜는 변환 전에 검사합니다. 잘못된 달력값을 일부 입력 형식에서 자동 보정할 수 있기 때문에 Date 객체가 만들어졌다는 사실만으로 날짜가 올바르다고 판단하지 않습니다.

일광절약시간(DST)을 쓰는 지역에서는 시계를 앞뒤로 조정하는 날이 있어 달력상 하루가 항상 24시간은 아닙니다. ‘해당 지역 다음 날짜의 자정’과 ‘24시간 뒤’를 구분해야 합니다. 이 예제의 현대 한국 시간 고정 오프셋은 그 지역·기간에 한정한 단순화입니다.

조회 기간이 같아도 늦게 들어온 성과가 추가되면 값이 달라질 수 있습니다. 기간은 **어느 때 발생한 데이터를 고르는지**, 집계 기준 시각은 **언제까지 반영된 집계를 보는지**를 설명합니다.

## 검증

시작 정각 포함, 시작 1ms 전 제외, 끝 1ms 전 포함, 끝 정각 제외를 확인합니다. 2월 30일 같은 잘못된 날짜를 JS가 자동 보정해 유효한 날짜로 받아들이지 않도록 입력 달력값을 검사합니다. 브라우저 시간대가 달라도 ISO 결과는 같아야 합니다.
