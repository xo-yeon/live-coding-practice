# 12. 내보낸 보고서가 화면 조건과 다르다

## 요구사항과 Before

현재 페이지가 아니라 현재 필터에 맞는 전체 결과를 내보냅니다. 내보내기 버튼을 누른 시점의 계정·기간·조건을 작업에 고정합니다. 서버 job ID로 완료를 확인합니다.

```ts
downloadCsv(currentPageRows);
```

## 재현과 우선순위

조건에 맞는 광고가 120개인데 첫 페이지 20개만 내려받습니다. 사용자는 전체 보고서라고 생각할 수 있습니다. 외부 보고와 수치 비교에 사용되는 기능이라면 데이터 완전성 문제입니다. 서버가 전체 결과를 내보내는 API를 제공하는지 먼저 확인합니다.

## After: 전체 결과와 조건을 서버 작업에 고정

```ts
// page를 내보내기 계약에서 제외. 조건은 원시값으로 복사
const snapshot = {
  accountId,
  from: filters.from,
  to: filters.to,
  status: filters.status,
  keyword: filters.keyword,
};
const job = await api.createExport(snapshot);
setExportJob({ id: job.id, snapshot });
```

화면 필터가 바뀌어도 이미 시작한 작업의 라벨·파일명은 snapshot 기준입니다. 응답 시점의 최신 필터로 파일명을 만들지 않습니다. “버튼 시점 조건”을 고정해도 그 사이 서버 데이터 자체가 바뀔 수 있습니다. 정확한 데이터 스냅샷이 필요하면 서버가 기준 시각·버전까지 보장해야 합니다.

폴링은 같은 요청이 끝나기 전에 다음 요청이 겹치지 않게 합니다. done·failed에서 중지하고 unmount·계정 변경에서도 정리합니다. 알려지지 않은 status는 영원히 로딩으로 두지 말고 응답 계약 오류로 처리합니다. 다운로드 권한은 서버가 검사합니다.

## 검증

전체 120개가 대상인지, 페이지 파라미터가 전달되지 않는지, 시작 후 필터를 바꿔도 job의 조건이 유지되는지 확인합니다. 완료·실패 후 더 이상 폴링하지 않는지, 이전 계정의 job 응답이 새 계정 화면에 연결되지 않는지 검사합니다. 실제 파일 행 수와 집계 기준 시각도 별도 통합 검증 대상입니다.

## 면접에서 말하기

> “화면 페이지 데이터는 전체 내보내기 범위와 다릅니다. 서버 작업에 클릭 시점 조건을 고정하고 작업 상태와 화면 조회 상태를 분리하겠습니다. 파일 내용의 기준 시각까지 일치해야 하는지는 추가로 확인하겠습니다.”

**꼬리질문:** 버튼만 disabled면 끝인가?

**해설:** 중복 클릭만 줄일 뿐 조건 불일치·전체 범위·계정 권한·폴링 정리는 해결되지 않습니다. 작업의 입력, 소유 계정, 수명과 결과 계약을 함께 정의해야 합니다.
