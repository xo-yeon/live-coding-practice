# 송금 예약 관리 — React/TypeScript 60분 모의면접

- Level 3 / 실제 코딩 면접 60분
- 선택 사항: 시작 전 코드 읽기 60분
- 모든 계좌·잔액·거래는 가상 데이터이며 실제 금융기관과 연결하지 않습니다.

## 상황

개인 고객이 생활비와 정기 지출을 예약하는 기능을 인수받았습니다.
팀은 빠르게 화면을 출시했고, 다음 배포 전에 기존 구현의 품질과 안정성을 검토하려고 합니다.
주어진 코드를 읽고 개선 우선순위를 설명한 다음, 제한 시간 안에 핵심 동작을 개선하세요.
모든 문제를 고치거나 전체 구조를 다시 만드는 것은 요구하지 않습니다.

## 사용자 요구사항

- 이름과 상태로 송금 예약을 조회하며, 화면은 현재 검색 조건에 해당하는 결과를 표시합니다.
- 계좌 요약에 잔액, 건별 송금 한도, 현재 목록 중 예약 상태인 송금액의 합계를 표시합니다.
- 예약은 양의 정수 원화 금액만 허용합니다. 쉼표를 포함한 금액 입력은 허용하지만 소수·음수·문자가 섞인 금액은 허용하지 않습니다. 잔액과 건별 한도를 초과할 수 없습니다.
- 받는 분, 은행, 8~14자리 숫자 계좌번호, 예약일을 입력해 새 예약을 만듭니다.
- 사용자가 한 번의 등록 의도로 제출한 예약은 한 건으로 처리하고 처리 중 상태를 알립니다.
- 예약 상태인 내역만 취소할 수 있습니다. 서버 처리 결과와 화면에 표시하는 결과가 일치해야 합니다.
- 상세 패널은 선택된 거래의 현재 내용을 보여줍니다.
- 통신 오류를 알려주며, 다시 조회하거나 다시 제출할 수 있어야 합니다.

## 과제 범위와 가정

수정 대상은 이 문제의 `working/`과 `tests/`입니다.
목 서버와 공통 실행 환경은 제공 코드이며 변경할 필요가 없습니다.
다른 연습 문제와 `before/`는 수정하지 않습니다.

- TypeScript strict를 유지합니다. 외부 라이브러리는 이미 설치된 TanStack Query를 사용해도 됩니다.
- 날짜는 시간 없는 YYYY-MM-DD 문자열입니다. 미래 날짜 제한·은행 영업일·시간대 계산은 이번 과제 범위에서 제외합니다.
- 계좌 객체의 `dailyLimit`은 기존 API 필드명입니다. 이번 요구사항에서는 **건별 한도**로 사용합니다.
- 예약 등록은 잔액을 즉시 차감하지 않습니다. 예약들의 합계가 잔액보다 큰지 확인하는 기능도 범위 밖입니다.
- 서버는 전달받은 금액의 유효성과 상태 전환을 검사합니다. 요청에 담긴 값이 사용자의 입력 의도와 같은지는 프런트엔드의 책임입니다.
- 실제 서비스의 서버 멱등성·인증·거래 승인·보안 설계 구현은 범위 밖입니다. 필요한 경우 한계를 설명하면 됩니다.

## 실행

저장소 루트에서 다음을 실행합니다.

```bash
pnpm dev
pnpm vitest practice/2026-09-21/04-scheduled-transfers/tests
```

브라우저: http://localhost:5173/practice/transfers

`working/TransferPage.tsx`가 이 화면의 진입점입니다.
코드를 저장하면 화면에 반영됩니다. 초기 데이터로 되돌리려면 브라우저를 새로고침합니다.
테스트는 매번 목 데이터를 초기화합니다.

## 테스트용 서버 동작

- 초기 내역은 5건이며 상태가 섞여 있습니다.
- 이름 검색은 부분 일치입니다. 한 글자 검색은 약 900ms, 나머지는 약 120ms가 걸립니다.
- 검색어 `오류`는 조회 실패 응답을 반환합니다.
- `최유진` 예약의 취소 요청은 실패합니다.
- 신규 예약 응답은 약 550ms, 취소 응답은 약 450ms가 걸립니다.
- 공개 테스트 통과는 모든 요구사항 충족을 의미하지 않습니다. 필요한 테스트를 추가하세요.
