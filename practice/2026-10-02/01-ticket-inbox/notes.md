# 분석 노트 — 정답 예시

## 발견한 문제

### 1. 상태 변경 후 목록이 갱신되지 않음

- 재현·현상: 상태를 `진행 중`으로 필터링하고 `Printer setup`의 `완료 처리`를 누르면, 해당 행이 진행 중 목록에 그대로 남습니다. 기존에 적어 둔 “버튼 클릭 시 상태변화 안됨”을 구체적인 조건과 화면 결과로 표현한 것입니다.
- 기대 / 실제: 상태 변경 직후 해당 행은 진행 중 목록에서 빠져야 하지만, 화면에는 이전 상태로 남습니다.
- 사용자 영향·우선순위: **높음.** 완료 여부를 잘못 판단하거나 버튼을 반복해서 누를 수 있습니다. 항상 재현됩니다.

### 2. 검색·필터가 상단 통계를 바꿈

- 재현·현상: `완료`만 표시하면 상단의 진행 중 건수가 0건이 됩니다.
- 기대 / 실제: 상단 통계는 전체 요청의 진행 중 2건을 유지해야 하지만, 필터링된 목록 기준으로 계산됩니다.
- 사용자 영향·우선순위: **높음.** 처리할 요청이 없다고 오판할 수 있습니다. 항상 재현됩니다.

### 3. 소문자 검색에서 결과가 누락됨

- 재현·현상: `printer`를 검색하면 `Printer`로 시작하는 요청이 나오지 않습니다.
- 기대 / 실제: 대소문자를 구분하지 않아 두 요청을 찾아야 하지만, 결과가 비어 있습니다.
- 사용자 영향·우선순위: **중간.** 사용자가 있는 요청을 찾지 못합니다. 같은 입력으로 재현됩니다.

## 수정 계획

- 원인과 최소 수정: `visible`을 별도 state와 Effect로 동기화하면서 원본 `tickets` 변경을 반영하지 못했습니다. `visible`을 현재 `tickets`, 검색어, 상태에서 바로 계산합니다. 상단 건수는 `tickets`에서 계산하고, 검색어와 제목은 모두 소문자로 바꿔 비교합니다.
- 제외할 범위·예상 위험: `TicketList`, 초기 데이터, 화면 구조와 라이브러리는 변경하지 않습니다. 필터 계산이 렌더마다 실행되지만 현재 4건에서는 의미 있는 성능 위험이 없습니다. 목록 규모가 커질 때만 측정 후 최적화를 검토합니다.

## 검증

- 수정 전 실패 테스트: `tests/challenge.test.tsx`에 4개를 추가했습니다. 소문자 검색, 전체 통계, 완료 처리 후 목록 갱신, 다시 열기 후 빈 결과가 각각 의도한 동작 차이로 실패했습니다. 기존 공개 테스트 2개는 통과했습니다.
- 수정 후 테스트·타입 검사: 해당 문제 **6/6 통과**, 전체 **28/28 통과**, `pnpm typecheck`와 `pnpm build` 통과. `pnpm lint`는 오류 0개이며 다른 기존 문제의 경고 2개가 남아 있습니다.
- 수동 확인·남은 위험: 브라우저 수동 조작은 실행하지 않았습니다. 필요하면 `진행 중` 필터 → `완료 처리` → `완료` 필터에서 표시 여부와 상단 건수를 확인합니다. 서버 저장은 공개 요구사항의 범위 밖입니다.
