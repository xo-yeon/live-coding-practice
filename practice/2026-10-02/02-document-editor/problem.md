# 팀 문서 편집기

Level 2 · 권장 코딩 40분 · 작업 파일 3개. 처음에는 시간 제한 없이 연습해도 됩니다. 사전 코드 읽기와 아래 테스트 학습 10~15분은 코딩 시간과 별개입니다.

## 상황

팀 안내문과 준비 체크리스트를 선택해 편집하고 저장하는 내부 도구입니다. 저장 API는 연습용입니다.

## 요구사항

- 문서를 선택하면 그 문서의 마지막 저장 내용을 편집란에 표시합니다. 저장하지 않은 편집을 남기고 다른 문서로 이동하면 초안은 버립니다.
- 저장 중에는 진행 상태를 표시하고 저장 버튼으로 중복 요청을 시작하지 않습니다. 문서 전환은 저장 중에도 가능합니다.
- 저장 성공 후 해당 문서의 저장 내용과 성공 상태를 표시합니다. 다른 문서를 보고 있다면 그 화면에 앞선 문서의 성공 상태를 표시하지 않습니다.
- 저장 실패 시 오류를 표시하고 입력한 초안을 유지합니다. 같은 내용으로 다시 저장할 수 있어야 합니다.
- 연습용 API는 300ms 뒤 응답합니다. 안내문의 첫 저장만 일시적으로 실패하고, 이후 저장은 성공합니다. API 계약과 지연 시간은 변경하지 않습니다.
- 공동 편집·충돌 해결·자동 저장은 범위 밖입니다. 외부 라이브러리 추가 없이 `working`에서 수정하고 필요한 테스트를 직접 추가하세요.

## 파일과 실행

`working/DocumentEditor.tsx` → `documentApi.ts` → `DocumentTabs.tsx` 순서로 읽어보세요. `before`는 원본, `working`은 수정 대상, `notes.md`는 분석 기록, `review.md`는 면접 후 기록입니다.

```bash
pnpm dev
pnpm vitest run practice/2026-10-02/02-document-editor/tests
pnpm typecheck
pnpm lint
```

화면: http://localhost:5173/practice/documents

공개 테스트는 시작 코드에서도 통과하는 기본 확인용이며 전체 요구사항을 보장하지 않습니다.

## 테스트 작성 학습

별도 예제로 비동기 검사를 연습합니다. **준비:** 클릭하면 Promise 완료 후 `완료`를 표시하는 작은 버튼을 렌더합니다. **행동:** 버튼을 클릭합니다. **기대 결과:** `await screen.findByText('완료')`로 최종 표시를 기다립니다. 요청 직후의 화면만 검사하면 비동기 결과를 놓칠 수 있습니다. 이 예제는 현재 문제의 테스트 정답이 아닙니다.

전체 코드를 설명하고 문제를 파악한 다음, 발견한 문제 하나의 기대 동작을 말로 정하세요. `tests/challenge.test.tsx`에 직접 재현 테스트를 추가해 수정 전에는 의도한 문제 때문에 실패하는지 확인합니다. 수정 후 같은 테스트를 통과시키고 실패 후 재시도 또는 문서 전환 같은 공개 경계 사례 하나를 더 검증하세요. 테스트 사이에 API 호출 횟수가 섞이지 않도록 필요하면 공개 테스트처럼 `save` 함수를 주입하세요.
