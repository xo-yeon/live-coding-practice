# 분석 노트 — 정답 예시

## 발견한 문제

### 1. 문서 전환 시 초안이 다른 문서에 남음

- 재현·현상: 안내문의 편집란에 새 내용을 입력한 뒤 저장하지 않고 체크리스트를 선택하면, 시작 코드에서는 안내문 초안이 체크리스트의 편집란에 남습니다.
- 기대 / 실제: 체크리스트의 마지막 저장 내용을 보여줘야 하며, 이전 문서의 미저장 초안은 버려야 합니다.
- 사용자 영향·우선순위: **높음.** 다른 문서에 잘못 저장할 수 있습니다. 사용자 풀이의 `selectDocument` 수정은 이 문제를 해결하는 방향이었습니다.

### 2. 저장 실패를 성공으로 표시하고 입력을 지움

- 재현·현상: 안내문의 첫 저장은 API 계약상 실패하지만, 시작 코드와 중간 풀이 모두 초안을 옛 내용으로 되돌리고 `저장되었습니다.`를 표시합니다.
- 기대 / 실제: 오류를 표시하고 사용자가 입력한 초안을 유지해야 같은 내용으로 재시도할 수 있습니다.
- 사용자 영향·우선순위: **높음.** 입력 손실과 저장 여부 오판이 동시에 일어납니다.

### 3. 저장 중 문서 전환 후 응답의 소속이 섞임

- 재현·현상: A 저장 버튼을 누르고 응답 전에 B로 이동하면, A의 응답으로 B 화면에 성공 표시가 나올 수 있습니다. 중간 풀이에서는 전환할 때 `status`가 `idle`로 바뀌어 B에서 중복 저장도 시작할 수 있었습니다.
- 기대 / 실제: 요청은 A에 귀속되며, B 화면에 A의 성공 상태를 표시하지 않아야 합니다. 저장 중 중복 요청도 막아야 합니다.
- 사용자 영향·우선순위: **높음.** 현재 문서가 저장되었다고 오판하거나 요청이 겹칠 수 있습니다. 관찰 조건은 “저장 후 전환”보다 **“저장 중 전환 후 응답”**이 정확합니다.

### 4. 공개 API 계약 변경

- 중간 풀이에서 `documentApi.ts`의 지연을 300ms에서 1000ms로 바꿨습니다. 요구사항에서 API 계약을 유지하도록 했으므로 300ms로 복구했습니다. 이것은 시작 코드의 숨은 결함이 아니라 풀이 과정에서 추가된 변경입니다.

## 수정 계획

- 원인과 최소 수정: `draft`는 선택 문서가 바뀌어도 자동으로 초기화되지 않습니다. 전환 시 해당 문서의 저장 내용으로 바꿉니다. 저장을 시작할 때 문서 ID와 입력 내용을 고정하고, 완료 시 현재 선택 문서와 비교해 알림을 표시합니다. 실패하면 초안을 건드리지 않고 오류를 표시합니다.
- 제외할 범위·예상 위험: 문서 전체를 순회해 편집 UI를 렌더링할 필요가 없어 기존 단일 편집 UI로 돌렸습니다. `DocumentTabs`와 저장 API 동작은 바꾸지 않습니다. 저장 중 추가 편집이 있으면 이전 요청의 성공이 새 초안을 저장한 것처럼 보이지 않도록 구분합니다.

## 검증

- 수정 전 실패 테스트: `tests/challenge.test.tsx`에 3개를 추가했습니다. 중간 풀이에서 문서 전환 테스트는 통과했지만, **실패 후 초안 유지·재시도**와 **A 저장 중 B 전환** 테스트는 의도한 동작 차이로 실패했습니다.
- 수정 후 테스트·타입 검사: 해당 문제 **5/5 통과**, 전체 **31/31 통과**, `pnpm typecheck`·`pnpm build` 통과. `pnpm lint`는 오류 0개이며 다른 기존 문제의 경고 2개가 남아 있습니다.
- 수동 확인·남은 위험: 브라우저 수동 조작은 실행하지 않았습니다. 필요하면 안내문 첫 저장 실패 → 같은 초안 재시도, A 저장 중 B 전환 → 응답 후 B 표시를 확인합니다. 공동 편집과 서버 충돌 처리는 공개 범위 밖입니다.
