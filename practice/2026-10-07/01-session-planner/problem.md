# 세션 일정 만들기

Level 2 · 권장 코딩 35분 · 작업 파일 3개. 처음에는 시간 제한 없이 연습해도 됩니다. 사전 코드 읽기와 테스트 학습 10~15분은 코딩 시간과 별개입니다.

## 상황

워크숍 참가자가 듣고 싶은 세션을 선택해 하루 일정을 만드는 화면입니다. 데이터는 브라우저에 고정된 연습용 목록입니다.

## 요구사항

- 각 세션의 시간은 시작을 포함하고 끝은 포함하지 않는 구간입니다. 한 세션이 10:00에 끝나고 다른 세션이 10:00에 시작하면 함께 선택할 수 있습니다.
- 시간이 겹치는 세션은 추가할 수 없으며, 기존 선택은 유지하고 안내를 표시합니다.
- 세션을 추가하거나 제거하면 버튼 표시, 선택한 일정과 개수가 즉시 바뀝니다. 선택한 일정은 시작 시각 순으로 보여줍니다.
- 세션을 제거한 뒤에는 이전 충돌 안내가 남지 않습니다. 세션 추가·시간 수정·서버 저장·드래그 정렬은 범위 밖입니다.
- 외부 라이브러리 추가 없이 `working`에서 수정하고 필요한 테스트를 직접 추가하세요.

## 파일과 실행

`working/SessionPlanner.tsx` → `sessions.ts` → `SessionList.tsx` 순서로 읽어보세요. `before`는 원본, `working`은 수정 대상, `notes.md`는 분석 기록, `review.md`는 면접 후 기록입니다.

```bash
pnpm dev
pnpm vitest run practice/2026-10-07/01-session-planner/tests
pnpm typecheck
pnpm lint
```

화면: http://localhost:5173/practice/sessions

공개 테스트는 시작 코드에서도 통과하는 기본 확인용이며 전체 요구사항을 보장하지 않습니다.

## 테스트 작성 학습

별도 작은 예제로 **준비 → 행동 → 기대 결과**를 연습합니다. `const values = [1, 2, 3]`을 준비하고, `values.filter((value) => value > 1)`을 실행한 뒤, `expect(result).toEqual([2, 3])`으로 결과를 확인합니다. 현재 문제의 테스트 정답은 아닙니다.

코드 전체를 설명하고 발견한 문제를 정한 뒤, 그 문제의 기대 동작을 말로 적으세요. `tests/challenge.test.tsx`에 재현 테스트를 직접 추가해 수정 전 의도한 이유로 실패하는지 보고, 수정 후 통과시키세요. 이어서 관련 경계 사례 하나를 더 검증합니다. 순수 시간 판단 함수 테스트부터 시작하고, 필요하면 클릭 후 표시까지 확인하세요.
