# 상품 검색

Level 2 · 권장 코딩 40분 · 작업 파일 3개. 처음에는 시간 제한 없이 연습해도 됩니다. 사전 코드 읽기와 테스트 학습 10~15분은 코딩 시간과 별개입니다.

## 상황

상품명으로 목록을 검색하고 페이지를 이동하는 화면입니다. 서버는 연습용 고정 데이터를 반환합니다.

## 요구사항

- 처음에는 전체 상품의 1페이지를 보여줍니다. 상품명 검색은 앞뒤 공백과 대소문자를 무시하며, 검색어를 바꾸면 1페이지부터 보여줍니다.
- 한 페이지에는 최대 두 상품을 표시합니다. 페이지 이동 버튼과 현재 페이지 표시는 **현재 검색어의 결과**를 기준으로 동작합니다. 결과가 없으면 빈 결과 안내를 표시합니다.
- 조회 중에는 로딩, 실패하면 오류와 `다시 시도`, 성공하면 상품 목록을 표시합니다. 실패 후 다른 검색어를 입력하거나 다시 시도해 결과를 받을 수 있습니다.
- 조회 중 검색어나 페이지를 바꿀 수 있습니다. 나중에 도착한 이전 요청이 현재 검색 조건의 화면을 덮어쓰면 안 됩니다.
- 연습용 API 계약: `desk` 검색은 700ms, 나머지는 150ms 뒤 응답합니다. `offline` 검색은 항상 실패합니다. API 데이터·지연·실패 조건은 변경하지 않습니다.
- 자동 재시도, 캐시, 실제 구매는 범위 밖입니다. 외부 라이브러리 추가 없이 `working`에서 수정하고 필요한 테스트를 직접 추가하세요.

## 테스트 작성 학습

별도 작은 예제로 **준비 → 행동 → 기대 결과**를 연습합니다. `const task = Promise.resolve('완료')`를 준비하고, `const result = await task`로 완료를 기다린 뒤, `expect(result).toBe('완료')`를 확인합니다. 화면 테스트에서는 요청 직후가 아니라 `findBy...` 또는 `waitFor`로 최종 표시를 기다립니다. 현재 문제의 테스트 정답은 아닙니다.

코드 전체를 설명하고 발견한 문제를 정한 뒤, 그 문제의 기대 동작을 말로 적으세요. `tests/challenge.test.tsx`에 재현 테스트를 직접 추가해 수정 전 의도한 이유로 실패하는지 보고, 수정 후 통과시키세요. 이어서 실패·재시도 또는 연속 검색 같은 공개 경계 사례 하나를 검증합니다. 테스트마다 `search` 함수를 주입하면 응답 순서와 실패를 독립적으로 제어할 수 있습니다.
