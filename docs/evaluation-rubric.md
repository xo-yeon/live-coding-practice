# 평가 기준 (100점)

| 항목                  | 점수 | 관찰 내용                                                   |
| --------------------- | ---: | ----------------------------------------------------------- |
| 문제 발견 정확도      |   20 | 실제 결함과 스타일 취향을 구분하고 핵심 문제를 찾는가       |
| 수정 우선순위와 근거  |   15 | 사용자·비즈니스 영향, 발생 가능성, 변경 위험으로 설명하는가 |
| 실제 동작과 버그 수정 |   25 | 최소 변경으로 재현된 문제를 고치고 회귀를 피하는가          |
| 코드 품질             |   20 | 가독성·예측 가능성·응집도·결합도가 나아졌는가               |
| 테스트와 검증         |   10 | 경계값과 사용자 동작을 검증하고 명령 결과를 확인하는가      |
| 의사소통              |   10 | 관찰·가설·선택·결과를 작업 중 명확히 말하는가               |

평가는 완벽한 구조보다 제한 시간 안의 판단 과정을 중시한다. 발견한 문제, 놓친 문제, 잘못 판단한 문제를 구분하며 과도한 변경도 감점 근거가 될 수 있다.
