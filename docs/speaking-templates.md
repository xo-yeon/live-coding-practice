# 라이브 코딩 말하기 템플릿

## 코드를 처음 볼 때

“먼저 현재 코드가 어떤 입력을 받고 어떤 결과를 만드는지 확인하겠습니다. 그다음 실제 오류 가능성이 있는 부분과 구조적인 개선 사항을 나눠서 보겠습니다.”

## 문제를 분류할 때

“이 부분은 단순한 가독성 문제가 아니라 원본 데이터를 변경하기 때문에 다른 화면의 결과에도 영향을 줄 수 있는 버그입니다.”

## 우선순위를 설명할 때

“현재는 사용자에게 잘못된 값을 보여줄 수 있는 문제를 먼저 수정하고, 구조 개선은 동작을 보존한 뒤 진행하겠습니다.”

## 최소 변경을 선택할 때

“제한된 시간 안에서는 영향 범위를 줄이기 위해 이 함수의 책임만 분리하겠습니다. 전체 구조 변경은 현재 요구사항에 비해 위험이 크다고 판단했습니다.”

## Effect를 제거할 때

“이 값은 다른 state에서 계산할 수 있는 파생 값이므로 별도 state와 Effect로 동기화하지 않고 렌더링 과정에서 계산하겠습니다.”

## 비동기 문제를 설명할 때

“요청 순서와 응답 순서가 항상 같다는 보장이 없기 때문에 이전 응답이 최신 결과를 덮어쓸 수 있습니다.”

## 테스트를 설명할 때

“정상 입력뿐 아니라 분모가 0인 경우와 빈 데이터처럼 실제 계산 결과가 깨질 수 있는 경계값을 먼저 검증하겠습니다.”

## 마무리할 때

“사용자 결과에 영향을 주는 핵심 문제를 우선 수정했고, 테스트와 타입 검사로 기존 동작을 확인했습니다. 시간이 더 있다면 남은 중복과 접근성 문제를 정리하겠습니다.”
